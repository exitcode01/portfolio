This document collects terminology used throughout Vista's documentation, with a brief explanation of each term.

## Client

A client is typically an application that consumes the response generated by the server and renders it to the user — for example, a Vista-backed UI table rendered in a browser.

## Controller

The controller is an element of a View UIControl: a Java class implementing the abstract `ViewController` class. Its responsibility is to help construct the `ViewModel` for a particular view.

## DataFetcher

Encapsulates the logic for fetching data from various datasources. It's the parent interface of all data fetcher classes — each child class implements how to fetch view data from its corresponding `DSContext`.

## Datasource entity

The metadata associated with datasource entities varies by datasource type. For relational datasources, entities refer to tables and columns; for GraphQL datasources, entities are represented by types and fields. This structure changes depending on datasource type, which is what allows Vista to stay flexible across different kinds of data models.

## DSContext

An abstract class that serves as the foundational structure for capturing contextual details related to a datasource. Vista provides `DSContext` implementations for each datasource type it supports.

## DSContextProvider

Responsible for supplying a `DSContext` instance — reads the relevant datasource configuration (such as a query) and constructs the corresponding `DSContext`.

## Elements

An element is the core part of a UIControl — what makes it possible to develop custom UIControls. A UIControl with a particular set of elements can be thought of as an *instance* of UIControl, given a name such as "View UIControl" or "Column UIControl." Elements are the moldable part of a UIControl.

## MDS view

Short for **multi-datasource view** — a view backed by more than one datasource at once, with results combined into a single response.

## SDS view

Short for **single-datasource view** — a view backed by exactly one datasource. The default and simplest case.

## Persister

The persistence of dynamic views is handled by implementations of the `DynamicViewPersister` interface. Such implementations are concisely referred to as "the persister."

## PreparedStatement

A feature of database connectivity libraries that provides an optimized way to execute SQL statements — especially useful when executing the same statement repeatedly with different parameter values, improving both performance and security against injection.

## Simple component

A minimal implementation of Vista's core architecture, used to build simple views. It uses only two entities: UIControl and Datasource — everything else in the fuller architecture is optional scaffolding on top of this minimal case.

## Simple view

A view built using a simple component — i.e., a view that only needs the minimal UIControl + Datasource pairing, with no additional pipeline organization.

## SQLSuite

The component responsible for query modification and related roles when working with hand-written SQL strings (`sql-string`) as a datasource, as opposed to Vista's structured query builder.
